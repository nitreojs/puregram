# @puregram/api

autogenerated bot api types, structures, updates, factories for [puregram](https://github.com/nitreojs/puregram) v3.

generated from `corefork.telegram.org/bots/api` (primary) and `core.telegram.org/bots/api` (supplementary). schema is parsed into `schema/<version>.json` and emitted to `src/generated/*.ts`.

## scripts

- `yarn parse` — scrape and produce `schema/<version>.json`
- `yarn emit` — read schema, write `src/generated/*.ts`
- `yarn regenerate` — parse then emit
- `yarn verify` — fail on drift between schema and generated

do not edit `src/generated/` by hand. it is rewritten on every emit.

## when the parser breaks

bot-api docs are HTML. when telegram changes the markup, the parser may emit incomplete or wrong schemas. symptoms:
- `yarn parse` throws with "unrecognized type: …" or "unexpected node …"
- the post-parse method/object counts drop sharply
- `yarn build` fails on the regenerated `src/generated/`

triage:
1. open the failing fixture / live URL. find the section that broke.
2. copy the offending HTML chunk into a new test fixture (`tests/fixtures/<scenario>.html`).
3. write a parser test that asserts the expected normalized output.
4. update `scripts/lib/parser/normalize.ts` (most likely) until the test passes.
5. re-run `yarn parse` to refresh `schema/<version>.json`.
6. re-run `yarn emit` and review the `src/generated/` diff in the PR.

parser maintenance cost is the price we pay for not depending on a third-party schema (ark0f). tracked in this README so the cost is visible.
